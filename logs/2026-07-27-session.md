# BusGlance / Waktu Session Log — 2026-07-27

Long session. Took BusGlance from a jumper-wire prototype to a trustworthy,
cordless device, rebuilt the case off the real board model, and made key

## Display / firmware (bus_display.ino)
- **3 bus timings per service** (NextBus/2/3): big next + two small raised numbers.
- **Dropped "min"** from the numbers; added a tiny **"MIN" legend** on the right of
  each bar.
- **"NOW" → "0"** (arriving = 0 min) — compact, no overlap.
- **Sticky weather**: keep last-good reading on a failed fetch instead of blanking.
- **Weather icon raised + rain drops shortened** so they clear the temp text.
- **Fail-loud failsafe** (the big safety win):
  - Retry NTP **every cycle** (was one-shot at boot) → clock self-heals.
  - Guard `minutesUntilArrival`: no valid clock → return -1 (kills the ~29M
    garbage minutes) + drop absurd (>240min) values.
  - **OFFLINE staleness banner**: if the LTA API isn't reached (or clock invalid)
    for >5 min, a black `! OFFLINE - times as of HH:MM` bar covers the top so
    stale times can never be mistaken for live.

## Hardware saga (all resolved)
- **Bent the ESP32 header pins flat** to slim the wire stack (two-pliers method).
- After rewiring, display froze / showed garbage → chased it down: NOT wiring or
  WiFi. Root cause = **NTP timeout on a cold boot** → no clock → 29M garbage
  minutes. Fixed by the failsafe above. (Also learned: `arduino-cli monitor`
  can't read serial through this CH340 dongle — the display is the ground truth,
  not the serial log.)
- **Battery: RESOLVED — it works.** It was just never fully charged. The board
  DOES auto-charge over USB-C; charge LED on = charging, off = full. Runs
  cordless ~7-10 days. Charge weekly.
- **Battery monitor: conclusively impossible on this board.** Ran an ADC scan
  (results shown on e-paper, since serial is dead) across GPIO 32/33/34/35/36/39
  — NO pin carries the battery voltage (all ~142mV floor; none near ~2000mV, none
  shift with USB). So the low-batt icon + ntfy push can't work without adding a
  2-resistor divider to GPIO 34. Decision: charge weekly, skip the monitor.
  Scanner kept at `adc_scan/adc_scan.ino`.

## Product / process decisions
- **Wall mount:** the printed keyholes were non-functional (no head clearance in
  a thin, packed case). Real answer for a light case = **velcro / Command
  strips** (removable, no wall damage). A slide-on bracket is the "proper" option
  if wanted later.
- **Closure:** no super glue (it's permanent AND cyanoacrylate fogs e-paper).
  Use screws / magnets / hot glue / tape.
- **"How do real products look clean inside?"** — custom PCB (bare ESP32 + RTC +
  FPC display connector, no dev board / jumper wires) + injection-molded case.
  The prototype's mess doesn't carry over; its job is to prove firmware + demand.
- **Red on e-paper:** would make refresh ~2× slower (~20s) AND force a ~3-min
  minimum interval → bad for a 60s bus display. Skip red; go true B/W for speed.

## Waktu (PRD updated — Drive-synced, not git)
- **Dropped ALL physical input** — no button, no touch, no rotary dial.
- **Setup via phone WiFi captive portal** (no app; fallback 192.168.4.1);
  **re-entry via power-cycle** ("the plug is the button"). Bluetooth rejected
  (needs an app). Cleaner case (no holes), cheaper BOM.
- RTC locked as **DS3231 (TCXO)** — DS1302/DS1307 drift ~1-2 min/month,
  unacceptable for prayer times; DS3231 ~±1 min/year.
- Prototype BOM ~$28-30; volume ~Rp200-290k vs Rp399-599k retail.
